## ЭТАП 1. Шаг 4: DDL (Архитектура таблиц — CREATE, ALTER, DROP)
Логика: Если DML управляет материей внутри ячеек, то DDL (Data Definition Language) создает, перестраивает и уничтожает сами физические контейнеры — таблицы, определяя правила игры на уровне диска.
------------------------------
## 1. Архитектурный синтаксис (Проектирование и модификация каркаса)

* Команда CREATE TABLE (Творение вселенной)

CREATE TABLE positions (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    base_salary NUMERIC(10,2) NOT NULL CHECK (base_salary > 0),
    created_at DATE DEFAULT CURRENT_DATE
);

Закон каркаса: Каждая колонка обязана получить жесткий тип данных и набор системных замков (ограничений).
* Команда ALTER TABLE (Модернизация на ходу)

ALTER TABLE positions ADD COLUMN department_id INT;ALTER TABLE positions ALTER COLUMN title TYPE VARCHAR(250);ALTER TABLE positions DROP COLUMN created_at;

* Команда DROP TABLE (Полная деструкция структуры)

DROP TABLE positions;


------------------------------
## 2. Главные капканы архитектора

* Капкан №1: Падение конвейера при дублировании (Table already exists)
Повторный запуск скрипта миграции CREATE TABLE вызовет жесткую ошибку сервера и остановит выполнение всего пакета команд.
* Щит защиты: Использование предохранителя существования:
   
   CREATE TABLE IF NOT EXISTS positions (...);
   
   * Капкан №2: Блокировка живой таблицы при ALTER TABLE
Смена типа данных колонки или добавление замка NOT NULL на таблице с миллионами строк заставит PostgreSQL принудительно переписать все файлы на диске. Сервер заблокирует таблицу для любых SELECT/INSERT запросов на время операции, парализовав продакшн.
* Щит защиты: Сначала колонка добавляется как пустая (NULL), данные заливаются пачками через DML, и только потом накладывается ограничение.
* Капкан №3: Каскадное обрушение при уничтожении (DROP TABLE с сиротами)
Попытка снести таблицу, на которую ссылаются другие таблицы через внешние ключи (FOREIGN KEY), будет заблокирована СУБД.
* Катастрофа при обходе: Если применить топор CASCADE, система молча удалит не только целевую таблицу, но и уничтожит все зависимые объекты (представления, ключи, дочерние таблицы):
   
   DROP TABLE categories CASCADE; -- Снесет категории и все мосты к ним.

## 3. Маневры профи

* Маневр «Слепок реальности» (CREATE TABLE AS)
Мгновенное создание новой физической таблицы на основе результата любого сложного SELECT запроса. Идеально для резервных копий перед тяжелыми манипуляциями.

CREATE TABLE backup_positions AS SELECT * FROM positions WHERE base_salary > 50000;

Капкан маневра: Новая таблица получит только структуру данных и строки. Индексы, автоинкременты (IDENTITY) и первичные ключи (PRIMARY KEY) оригинальной таблицы на новый слепок не копируются.
