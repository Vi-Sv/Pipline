## ЭТАП 1. Шаг 5: Связующие замки (PRIMARY KEY / FOREIGN KEY)
Логика: Мосты, которые вы строили в JOIN, держались на честном слове (логическом совпадении). Связующие замки DDL переводят это на уровень системного закона. Они физически запрещают банить логику данных и рождать «сирот».
------------------------------
## 1. Архитектурный синтаксис (Монтаж замков)
Мы создаем главную таблицу-родителя и дочернюю таблицу, жестко приковывая её цепью внешнего ключа (FOREIGN KEY) к первичному ключу (PRIMARY KEY) родителя.

-- Таблица-Родитель (Остров №1)CREATE TABLE objects (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY, -- Главный замок уникальности
    object_name VARCHAR(250) NOT NULL
);
-- Таблица-Потомок (Остров №2)CREATE TABLE supply_orders (
    order_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    object_id INT NOT NULL,
    material_title VARCHAR(150) NOT NULL,
    
    -- Монтаж соединительного моста намертво
    CONSTRAINT fk_supply_object 
    FOREIGN KEY (object_id) REFERENCES objects(id)
);

------------------------------
## 2. Главные капканы связующих замков

* Капкан №1: Сироты войны (Foreign key violation при INSERT)
Попытка вставить в supply_orders строку с object_id = 99. Если в главной таблице objects нет строки с id = 99, база данных жестко заблокирует операцию. Нельзя поставить материал на несуществующий объект.
* Капкан №2: Разрушение фундамента (Foreign key violation при DELETE)
Попытка удалить объект из таблицы objects, на который уже завязаны строки поставок в supply_orders. База выдаст ошибку и защитит данные от появления сирот.

------------------------------
## 3. Маневры профи (Управление поведением моста)
Чтобы автоматизировать удаление или изменение родительских данных, при объявлении FOREIGN KEY задаются правила реагирования:

* Маневр «Зачистка хвостов» (ON DELETE CASCADE)
Уничтожение родителя автоматически выжигает всех потомков. Удаляем объект — база сама сносит все его поставки.

FOREIGN KEY (object_id) REFERENCES objects(id) ON DELETE CASCADE

* Маневр «Амнистия» (ON DELETE SET NULL)
При удалении родителя строки-потомки выживают, но их связующий гонец зануляется (NULL). Объект удален, но история поставок осталась с пометкой «Объект неизвестен».

FOREIGN KEY (object_id) REFERENCES objects(id) ON DELETE SET NULL

Закон: Чтобы этот маневр сработал, колонка object_id в дочерней таблице обязана быть без замка NOT NULL.
