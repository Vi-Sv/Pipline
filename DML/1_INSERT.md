## ЭТАП 1. Шаг 1: Инструмент INSERT (Генератор материи)
Логика: Если SELECT создает виртуальную проекцию в RAM, то INSERT совершает физический акт творения — берет сырые данные и жестко вшивает их на диск хранилища в виде новых строк.
## 1. Архитектурный синтаксис (Два боевых режима)

* Режим №1: Дисциплинированный (Профессиональный стандарт)
Мы явно объявляем адреса колонок, а затем передаем им груз.

INSERT INTO users (id, user_name, user_role) VALUES (1, 'Иван', 'Инженер');

Закон: Порядок значений в VALUES обязан зеркально повторять порядок объявленных колонок.
* Режим №2: Скоростной слепой (Категорически запрещен на производстве)
Колонки не объявляются, данные засыпаются навалом.

INSERT INTO users VALUES (1, 'Иван', 'Инженер');

Катастрофа режима: Если завтра архитектор добавит в середину таблицы колонку registration_date, ваш слепой запрос мгновенно разобьется о несоответствие типов данных и уронит конвейер.

------------------------------
## 2. Главные капканы генератора материи

* Капкан №1: Нарушение уникальности (Unique violation)
Попытка вставить строку с ID, который уже зафиксирован в системе на позиции PRIMARY KEY. Сервер заблокирует транзакцию и выкинет ошибку.
* Щит защиты (Амортизатор ON CONFLICT): Мы приказываем системе перехватить ошибку прямо на лету:
   
   INSERT INTO users (id, user_name) VALUES (1, 'Иван')ON CONFLICT (id) DO NOTHING; -- Наткнулся на дубль? Просто игнорируй и иди дальше.
   
   * Капкан №2: Пустота в монолите (NOT NULL violation)
Попытка проигнорировать колонку, на которой стоит системный замок «Запрещено быть пустым» (NOT NULL), если у этой колонки нет автоматического дефолтного значения (DEFAULT).

------------------------------
## 3. Маневры профи

* Маневр «Обойма» (Множественная вставка)
Запрещено дергать сервер ради одной строки тысячу раз. Строки сцепляются через запятую в один мощный пакет:

INSERT INTO users (id, user_name) VALUES 
    (2, 'Петр'),
    (3, 'Сидор'),
    (4, 'Елена'); -- Один приказ — три физические строки на диске.

* Маневр «Ракетный выстрел» (INSERT INTO ... SELECT)
Используется, когда нужно перекачать миллионы строк из одной таблицы в другую (например, архивную). Блок VALUES упраздняется, его место занимает боевой SELECT:

INSERT INTO archive_users (id, user_name)SELECT id, user_name FROM active_users WHERE last_activity < '2025-01-01';

* Маневр «Эхо» (RETURNING)
По умолчанию INSERT молча пишет данные на диск и возвращает сухой технический отчет. Если вам нужно мгновенно увидеть, как СУБД сгенерировала автоматический ID или применила дефолтные значения, используйте RETURNING в самом конце:

INSERT INTO users (user_name) VALUES ('Алексей') 
RETURNING id, registration_date; -- Мгновенно выведет сгенерированные сервером данные на экран.
