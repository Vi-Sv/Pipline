## ЭТАП 1. Шаг 2: Инструмент UPDATE (Хирургическая модификация)
Логика: UPDATE не создает новые строки и не уничтожает старые. Он заходит внутрь уже существующих на диске строк и перезаписывает значения в конкретных ячейках («замена деталей на ходу»).
## 1. Архитектурный синтаксис
Мы указываем таблицу для модификации, через оператор SET задаем новые значения и жестко ограничиваем зону поражения через сито WHERE.

UPDATE users SET user_role = 'Старший инженер', salary = salary * 1.1WHERE id = 42;

Закон: Изменение нескольких колонок внутри одной строки перечисляется строго через запятую после одного оператора SET.
------------------------------
## 2. Главные капканы хирургической модификации

* Капкан №1: Ядерный взрыв (Отсутствие WHERE)
Если написать UPDATE и забыть поставить сито WHERE, сервер не выдаст предупреждение. Он выполнит приказ буквально: перепишет указанные ячейки абсолютно во всех миллионах строк таблицы.
* Щит защиты: На производстве перед выполнением любого UPDATE сначала пишется тестовый SELECT с тем же самым условием WHERE, чтобы точно увидеть строки, которые пойдут под нож хирургу.
* Капкан №2: Подмена реальности во время расчета
Если в блоке SET вы одновременно обновляете колонку и используете её старое значение для расчета другой колонки, PostgreSQL берет исходное значение строки до начала транзакции.

-- salary = 1000, bonus = 100UPDATE employees SET salary = 2000, bonus = salary * 0.1 WHERE id = 1;-- Итог: salary станет 2000, но bonus станет 100 (1000 * 0.1), а не 200.


------------------------------
## 3. Маневры профи

* Маневр «Трансфер из чужого мира» (UPDATE FROM)
Используется, когда новые значения для обновления нужно взять из другой таблицы (мост на этапе модификации).

UPDATE employees AS eSET salary = s.new_salaryFROM salary_grades AS sWHERE e.grade_id = s.id AND e.department = 'ПТО';

Закон префиксов: В блоке SET обновляемая колонка пишется без префикса таблицы (salary = ...), а таблица-донор в блоке FROM обязательно получает алиас для точечной адресации в WHERE.
* Маневр «Эхо модификации» (RETURNING)
Как и в INSERT, чтобы не делать повторный SELECT для проверки измененных данных, мы заставляем систему выплюнуть результат операции на экран:

UPDATE users SET user_role = 'Архитектор' WHERE id = 5 
RETURNING id, user_role, updated_at; -- Сразу покажет измененную строку.
