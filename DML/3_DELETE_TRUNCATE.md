## ЭТАП 1. Шаг 3: Инструменты DELETE и TRUNCATE (Аннигиляция материи)
Логика: Оба инструмента уничтожают данные, но делают это на абсолютно разных физических уровнях. DELETE — это хирургический пинцет, который извлекает строки через сито фильтра. TRUNCATE — это промышленный шредер, который сносит внутренности таблицы целиком на уровне файловой системы.
------------------------------
## 1. Архитектурный синтаксис

* Режим DELETE (Выборочное удаление):

DELETE FROM users WHERE status = 'fired' AND last_activity < '2025-01-01';

* Режим TRUNCATE (Полная зачистка):

TRUNCATE TABLE heavy_logs;


------------------------------
## 2. Главные капканы аннигиляции

* Капкан №1: Тотальное выжигание (DELETE без WHERE)
Если запустить DELETE FROM table; без блока WHERE, сервер методично, строка за строкой, удалит все данные.
* В чем отличие от TRUNCATE: При этом СУБД будет честно генерировать логи для каждой удаленной записи (WAL-логи), проверять триггеры и тратить ресурсы RAM. Операция на миллионах строк заставит базу захлебнуться.
* Капкан №2: Ловушка счетчика (SERIAL / IDENTITY)
Обычный DELETE и базовый TRUNCATE очищают строки, но оставляют счетчик автоинкремента (ID) в покое. Если в таблице был максимальный ID = 100, то после удаления всех строк новая запись получит ID = 101.
* Щит защиты: Сброс счетчика под ноль контролируется явной надстройкой в TRUNCATE:
   
   TRUNCATE TABLE users RESTART IDENTITY; -- Стирает данные и сбрасывает счетчик ID в 1.
   
   * Капкан №3: Каскадный блок (Foreign Key Violation)
Если на таблицу завязаны другие «острова данных» через связи FK, сервер жестко заблокирует удаление записей, чтобы не оставить сирот в дочерних таблицах.

------------------------------
## 3. Маневры профи

* Маневр «Удаление по наводке» (USING)
Используется в DELETE, когда нужно уничтожить строки на основе условий из совершенно другой таблицы (мост для зачистки).

DELETE FROM orders AS oUSING clients AS cWHERE o.client_id = c.id AND c.status = 'blacklisted';

* Маневр «Эхо аннигиляции» (RETURNING)
Позволяет перехватить и посмотреть на данные, которые только что были стерты навсегда, до того как они исчезнут из памяти:

DELETE FROM sessions WHERE expired_at < NOW() 
RETURNING session_id, user_id; -- Выведет на экран список уничтоженных сессий.


------------------------------
## Сравнительный паспорт: Битва титанов зачистки

| Критерий | DELETE | TRUNCATE |
|---|---|---|
| Скорость выполнения | Медленно (построчно) | Моментально (блоками данных) |
| Сито WHERE | Разрешено | Категорически запрещено |
| Влияние на логи (WAL) | Пишет лог под каждую строку | Пишет одну запись об очистке класса |
| Срабатывание триггеров | Да, на каждую строчку | Нет, игнорирует построчные триггеры |
| Откат (ROLLBACK) | Да, полностью безопасен | Да (в PostgreSQL), восстановит файлы |
