## ЭТАП 2. Шаг 2: Индексы (Скоростные рельсы — B-Tree, BRIN)
Логика: Без индексов любой SELECT с фильтром WHERE — это линейный перебор (Seq Scan). Сервер вынужден лопатить миллиард строк с диска, ища одну ячейку. Индекс — это упорядоченный каталог-указатель. Сервер прыгает сразу к физическому адресу строки, минуя чтение всей таблицы.
------------------------------
## 1. Архитектурный синтаксис (Монтаж рельсов)

* Тип №1: Стандартный B-Tree (Сбалансированное дерево)
Идеален для точечных выстрелов по уникальным ID, текстам или статусам. Работает со сравнениями (=, >, <, IN, BETWEEN).

CREATE INDEX idx_users_email ON users(email);

* Тип №2: Промышленный BRIN (Block Range Index)
Создан для терабайтных таблиц с логами или датами, которые пишутся строго в хронологическом порядке. Занимает в 1000 раз меньше места, чем B-Tree, так как хранит только диапазоны значений для блоков данных.

CREATE INDEX idx_logs_date ON heavy_logs USING brin(created_at);


------------------------------
## 2. Главные капканы скоростных рельсов

* Капкан №1: Избыточное раздувание диска и RAM
Каждый индекс — это отдельный скрытый файл. При каждом вашем INSERT, UPDATE или DELETE сервер обязан перестраивать этот индекс в RAM и на диске. Если навесить по индексу на каждую колонку, скорость записи данных упадет в разы.
* Капкан №2: Внезапное отключение индекса из-за функций ювелира
Если на индексированной колонке применить трансформацию в блоке WHERE, сервер ослепнет. Индекс станет бесполезен, и СУБД рухнет обратно в линейный перебор (Seq Scan).

-- Индекс на email создан. Но этот запрос ЕГО ИГНОРИРУЕТ:WHERE LOWER(email) = 'test@mail.ru'; -- Коллапс. Индекс не работает.

Щит защиты (Функциональный индекс): Мы создаем рельсы сразу под готовую трансформацию:

CREATE INDEX idx_users_lower_email ON users(LOWER(email));


------------------------------
## 3. Маневры профи

* Маневр «Покрывающий индекс» (INCLUDE)
Позволяет отдавать данные из SELECT вообще без похода к самой физической таблице. Данные считываются напрямую из самого файла индекса.

CREATE INDEX idx_orders_perf ON orders(client_id) INCLUDE (amount);-- Запрос SELECT client_id, amount FROM orders WHERE client_id = 5 выполнится мгновенно.

* Маневр «Частичный щит» (WHERE)
Зачем индексировать всю таблицу, если мы ищем только по активным строкам? Мы жестко режем размер самого файла индекса.

CREATE INDEX idx_active_orders ON orders(id) WHERE status = 'in_progress';
