## ЭТАП 2. Шаг 1: Транзакции (Броня ACID — BEGIN, COMMIT, ROLLBACK)
Логика: Транзакция — это силовой кокон, который объединяет несколько команд DML (INSERT, UPDATE, DELETE) в одну неделимую атомную операцию. Для диска СУБД больше не существует отдельных запросов; вся пачка выполняется по принципу «всё или ничего».
------------------------------
## 1. Архитектурный синтаксис (Управление коконом)
Мы открываем транзакцию, выполняем серию хирургических манипуляций и принимаем финальное решение: вшить изменения на диск намертво (COMMIT) или полностью стереть следы операции из памяти, откатив СУБД к исходной точке (ROLLBACK).

BEGIN; -- Шаг 1: Открытие силового кокона
-- Шаг 2: Списание со склада (Операция А)UPDATE warehouse_stocks SET quantity = quantity - 50 WHERE material_id = 12 AND warehouse_id = 1;
-- Шаг 3: Оприходование на объект (Операция Б)INSERT INTO object_supplies (object_id, material_id, quantity) VALUES (5, 12, 50);
COMMIT; -- Шаг 4: Фиксация. Изменения физически записаны на диск.

Если на Шаге 3 произошел сбой (выключился свет, упал сервер или сработал замок NOT NULL), мы пишем ROLLBACK; — и склад моментально возвращает свои 50 единиц, будто ничего не происходило.
------------------------------
## 2. Главные капканы транзакций

* Капкан №1: Взаимная блокировка строк (Deadlock)
Происходит, когда две параллельные транзакции пытаются обновить одни и те же строки в разном хронологическом порядке.
* Механика: Транзакция №1 заблокировала Строку А и ждет Строку Б. Транзакция №2 одновременно заблокировала Строку Б и ждет Строку А. Система встает намертво. PostgreSQL через несколько секунд принудительно убьет одну из транзакций ошибкой deadlock detected.
   * Щит защиты: Строгий закон конвейера — любые таблицы во всех скриптах автоматизации всегда должны обновляться в абсолютно одинаковом порядке (например, строго по возрастанию ID).
* Капкан №2: Аномалии чтения (Фантомы и Грязные данные)
Если одна транзакция считает данные, пока вторая их меняет, но еще не сделала COMMIT, первая транзакция может увидеть галлюцинацию — данные, которых физически еще нет на диске.
* Щит защиты: Управление уровнями изоляции. По умолчанию в PostgreSQL стоит уровень Read Committed (грязное чтение физически невозможно). Для железной изоляции всей выборки перед BEGIN задают уровень:
   
   SET TRANSACTION ISOLATION LEVEL SERIALIZABLE; -- Полная консервация данных.

## 3. Маневры профи

* Маневр «Точка сохранения» (SAVEPOINT)
Позволяет делать промежуточные бэкапы внутри одной длинной транзакции и откатываться не в самый ее старт, а на конкретный рубеж.

BEGIN;INSERT INTO logs VALUES (1, 'Старт');
SAVEPOINT step_one; -- Поставили флаг
UPDATE users SET status = 'active'; -- Опасная операция-- Поняли, что ошиблись:ROLLBACK TO step_one; -- Откатили только UPDATE. Лог из шага 1 выжил.
COMMIT; -- Зафиксировали лог.
