# Ультимативное BI-руководство: Сборка отчета с нуля
Этот документ — универсальный боевой алгоритм для развертывания BI-отчетности в любой системе. Архитектура процессов идентична во всем мире: будь то Yandex DataLens (РФ-стандарт), Power BI (мировой лидер) или Apache Superset (Open Source).

---

##  1. Архитектурный конвейер (4 звена цепи)

Данные проходят строго линейный путь. Разрыв любого звена полностью ломает отчет.

1. **Источник (Data Source):** Место, где физически лежат данные (ваша база PostgreSQL).
2. **Подключение (Connection):** Технический мост (логин, пароль, хост), открывающий BI-системе доступ к источнику в режиме "только чтение".
3. **Датасет (Dataset):** Логическая модель данных внутри BI. Здесь вы выбираете нужные таблицы, строите мосты (JOIN) между ними или заливаете сырой SQL-запрос.
4. **Чарты и Дашборд (Charts & Dashboard):** Финальная визуальная проекция. Чарты — это отдельные графики, Дашборд — единый экран, куда эти графики собираются и снабжаются фильтрами.

---

##  2. Универсальная таблица соответствия терминов

При переходе из одной BI-системы в другую меняются только названия кнопок, но не суть:

| Логический узел | В Yandex DataLens | В Power BI | В Apache Superset |
| :--- | :--- | :--- | :--- |
| **Технический мост** | Подключение | Источник данных (Gateway) | Connection |
| **Модель данных** | Датасет | Модель данных / Power Query | Dataset |
| **Строка данных** | Измерение (Dimension) | Измерение / Текстовое поле | Dimension |
| **Агрегированное число**| Показатель (Measure) | Мера (DAX Measure) | Metric |
| **Отдельный график** | Чарт | Визуальный элемент | Chart / Slice |

##  3. Пошаговый боевой алгоритм (На примере Yandex DataLens)

### Шаг 1: Прокладка моста (Подключение)
1. В интерфейсе нажимаете **Создать** -> **Подключение**.
2. Выбираете **PostgreSQL**.
3. Вводите реквизиты: Имя хоста, Порт, Имя базы, Логин и Пароль.
4. Нажимаете **Проверить подключение**. Если загорелся зеленый щит — жмете **Создать подключение**.

### Шаг 2: Создание датасета (Сборка каркаса)
1. Внутри созданного подключения жмете **Создать датасет**.
2. **Капкан перегрузки:** Перетаскивание таблиц мышкой заставит BI делать неконтролируемые `JOIN` на стороне базы. 
3. **Щит защиты (Режим профи):** Нажимаете кнопку **Изменить SQL**. Вставляете ваш оптимизированный, очищенный через `EXPLAIN ANALYZE` запрос `SELECT`. Жмете **Применить**.
4. База выдаст список полей. BI автоматически разделит их на два лагеря:
   * **Измерения (Зеленые):** Текст, даты, ID (то, по чему мы группируем и фильтруем).
   * **Показатели (Синие):** Числа, суммы, количество (то, что мы математически считаем). Нажмите на функцию агрегации для чисел и жестко выставите `СУММА` или `КОЛИЧЕСТВО`.

### Шаг 3: Производство графиков (Чарты)
1. В датасете жмете **Создать чарт**. Вы попадаете в конструктор.
2. Выбираете тип визуализации (Таблица, Линейная диаграмма, Столбчатая диаграмма).
3. Перетаскиваете мышкой:
   * Измерение (например, `Дата`) -> в секцию **X** (Ось времени).
   * Показатель (например, `Сумма сметы`) -> в секцию **Y** (Высота столбца).
4. Нажимаете **Сохранить** и называете чарт (например, "Динамика затрат").

### Шаг 4: Монтаж единого экрана (Дашборд)
1. Нажимаете **Создать** -> **Дашборд**.
2. Нажимаете **Добавить** -> **Чарт**. Выбираете созданный ранее график.
3. Нажимаете **Добавить** -> **Селектор (Фильтр)**. Привязываете его к полю `Дата` или `Объект`. Теперь пользователь может одной кнопкой перестраивать все графики на экране.

##  4. Универсальный язык формул (Форматирование на лету)

Если данные в датасете требуют финальной ювелирной огранки, внутри датасета нажимают кнопку **Добавить поле**. Синтаксис формул DataLens практически идентичен стандартному SQL.

*   **Борьба с пустотой (Аналог `COALESCE`):**
    ```sql
    IFNULL([Fakt_Cost], 0) -- Если факт пустой, выводит ноль, защищая математику
    ```
*   **Текстовый ювелир (Аналог `TRIM` и `CONCAT`):**
    ```sql
    LCASE(TRIM([Object_Name])) -- Зачистка невидимых пробелов и перевод в нижний регистр
    ```
*   **Хирургия дат (Округление до месяца):**
    ```sql
    DATE_TRUNC([Order_Date], "month") -- Отсекает дни, превращая '2026-08-25' в '2026-08-01'
    ```
*   **Логический тумблер (Аналог `CASE WHEN`):**
    ```sql
    IF [Salary] > 100000 THEN 'High' ELSE 'Low' END -- Маркировка строк по условию
    ```

##  5. Главные капканы BI-разработки

*   **Капкан №1: Расчет мер в Excel-стиле**
    *   *Суть:* Считать среднюю цену как среднее арифметическое от готовых средних цен в таблице. Математически это ложь.
    *   *Щит защиты:* BI должен всегда считать от сырых первичных данных. Сначала пишется общая сумма, затем делится на общее количество: `SUM([Total_Cost]) / SUM([Total_Volume])`.
*   **Капкан №2: Визуальный хаос (Цыганщина)**
    *   *Суть:* Использование 10 разных цветов, круговых диаграмм на 50 секторов и 3D-графиков. Бизнес не поймет такой отчет.
    *   *Щит защиты (Коммерческий стандарт):* Один дашборд — одна бизнес-мысль. Не более 4–5 графиков на одном экране. Используйте строгую корпоративную палитру (нейтральный серый/синий акцент). Вместо круговых диаграмм всегда используйте обычную горизонтальную линейную таблицу — человеческий глаз считывает длину полосы в разы точнее, чем сектор круга.
